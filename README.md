# 私密密码库

Windows x64 与 Android 8.0 及以上的个人密码记录软件。打开即可查看，支持离线新增、修改、删除、搜索、复制和冲突选择。通用安装包没有预置任何人的密码库、密钥或服务器地址，新用户可以新建独立密码库，或从已有文件恢复。

源码采用 MIT 许可。安装包与源码：[GitHub Releases](https://github.com/Laz1do/private-vault-open/releases)。**0.3.0 发布 Windows 新界面与可选 Chrome 扩展；Android 继续使用 0.2.0 APK，本轮不发布新的 APK。** Windows 包未购买商业代码签名；Android APK 使用项目的私有发布密钥签名。两端继续使用同一 `.pvault` 文件格式及服务器协议。

## Windows 0.3.1

0.3.1 提高了桌面与扩展的文字可读性。密码列表直接提供“复制账号／复制密码”，复制成功或失败在原按钮显示；输入即时筛选，并提供“查找”按钮。导航选中背景连续移动，动效尊重系统减少动态效果设置。更新方法见 [0.3.1 升级说明](docs/UPGRADE-0.3.1.md)。

浅色／深色外观随系统，界面分为“密码库”“浏览器助手”“文件与恢复”“设置”。列表与详情保留搜索、复制、编辑和冲突选择。按钮按压与弹窗使用短促反馈，搜索和快捷键立即响应；系统启用减少动态效果时，位移动画收敛为淡入淡出。

第一次打开，选择“新建密码库”或“从文件恢复”。在“文件与恢复”中可以随时**生成当前库的恢复文件**。已有密码库时选择“新建密码库”，必须先成功保存旧库的完整恢复文件，再切换到新的空库；取消保存、保存失败或新库提交失败均继续使用旧库。本地同时只使用一个密码库，新库从文件模式开始，旧库的服务器数据不被删除。

关闭 Windows 窗口后，软件保留在系统托盘，继续处理浏览器填写、保存与同步。双击托盘图标恢复窗口，选择托盘菜单“退出”才会停止软件。升级步骤见 [0.3.0 升级说明](docs/UPGRADE-0.3.0.md)。

## 可选 Chrome 浏览器助手

先安装 Windows 0.3.0，进入“浏览器助手”开启功能，再从发布页下载扩展 ZIP，解压到长期保存的文件夹。在 Chrome 打开 `chrome://extensions`、开启“开发者模式”，点击“加载已解压的扩展程序”，选择含 `manifest.json` 的文件夹。也可以从软件中点击“打开扩展目录”，加载它打开的目录。Windows 客户端自动为固定扩展 ID 注册本机连接，无需输入账号、密钥或扩展 ID。

在 HTTPS 页面打开扩展小窗，显示精确匹配当前网站的账号。**按 HTTPS 来源匹配主机名和端口**：`login.example.com` 不匹配 `shop.example.com`，非默认端口也各自隔离。点击账号后填写，登录由你提交；不会自动点击登录。没有网址或存在冲突的记录不参与填写，冲突先在软件里处理。账号与密码分步输入时，在各自页面分别点选账号。

若需要检测新密码，在扩展小窗开启“网站检测”，允许访问所有 HTTPS 网站。启用后它识别主页面提交的登录、注册和改密表单，生成待确认候选；核对小窗中的网站、账号和密码后，才会保存或更新密码库。多条记录需要选择更新目标，更新保留原名称和备注。填写与自动检测都可关闭。详细权限、安装和限制见 [Chrome 扩展说明](chrome/README.md)。

自动识别不表示登录成功。此版本不填写验证码或子框架登录，不保证所有网站及登录路径；动态字段、跨网站分步登录和无法区分新旧密码的表单可能需要手动录入。

## 两种更新方式

**文件模式（默认）**：Windows 在“文件与恢复”中点击“生成恢复文件”，自行复制给另一台设备，再点击“导入与合并”；Android 0.2.0 的对应按钮为“导出文件”和“导入文件”。每次导出是当时完整库的快照；后续编辑不会自动写回已经导出的文件。此模式不访问同步服务器。

**服务器模式**：连接你自己部署的 HTTPS 服务器。软件打开、回到前台、修改记录、恢复网络及手动同步时尝试更新。Windows 关闭窗口后留在托盘，修改记录仍会触发同步；明确退出软件后停止同步。Android 下次打开或回到前台时尝试更新。切回文件模式保留同一份本地密码库并停止服务器同步。

导入同一库文件会合并记录，保留本机独有的新记录；旧文件不会覆盖较新修改或恢复已删除的密码。同一记录被两台设备分别修改时保留冲突版本，由你选择。没有历史版本、撤销或回收站。首次使用的新空库可以接纳已有文件；已经有记录或删除标记的库拒绝其他库的文件。相同库 ID 但密钥不同的文件也会拒绝，失败不会修改现有库。

## 文件与本机存储

**导出的 `.pvault` 文件无需密码，任何持有人都能读取密码，并获得文件内对应服务器的访问权限。** 文件含完整密码记录、库密钥、库 ID、服务器地址和访问凭据，只传递给你认可的设备。软件在导出/导入处也说明这一点。

软件自己的工作副本采用 AES-256-GCM 加密；Windows 用系统 `safeStorage` / DPAPI 保护配置，Android 用 AndroidKeyStore 保护配置。没有主密码，依靠设备账户和锁屏保护。本机配置和密文一起原子提交；损坏文件不会自动当作空库覆盖。你负责设备与导出文件的保管。

服务器只接收 AES-GCM 密文与库 ID，不接收库密钥或明文密码，使用访问凭据的 SHA-256 摘要鉴权。一个服务器实例对应一个库，其他用户自行建库和部署自己的实例。

## 自建服务器

1. 在软件中新建记录或保持空库，生成一个 `.pvault` 恢复文件。
2. 在装有 Node.js 22 或更新版本的**本机**，用源码中的工具生成服务器配置：

   ```sh
   node tools/server-config.mjs --file /path/to/passwords.pvault --out server/server.env
   ```

   输出只有库 ID、访问凭据摘要和运行参数。工具不覆盖已有配置。密码文件、库密钥和原始访问凭据留在本机，不复制到服务器。
3. 将 `server/` 的程序和生成的 `server.env` 复制到你的服务器。按 [服务器部署说明](server/README.md) 提供 HTTPS。
4. 在软件的服务器设置中填 HTTPS 根地址，保留软件生成的访问凭据，然后切换到服务器模式。
5. 重新导出文件，交给另一台设备导入；文件会带上连接配置。另一台设备切换到服务器模式后即可下载和合并同一库。

改变访问凭据后，服务器的摘要配置也必须同步修改。修改服务器地址不改变库身份；错误的服务器库 ID 或密钥会停止同步并保留本地数据。

## 从 0.1.0 专属版升级

0.1.0 安装包自带专属密钥，0.2.0 及更新通用安装包不再携带它。更新前保留旧安装包和专属配置备份。通用版发现旧 `vault.json` 而缺少原密钥时，会进入“导入恢复”状态，保留旧文件并暂停编辑与同步；导入带原库身份与密钥的 `.pvault` 文件后会解密原本地记录并合并，保留设备身份。

旧专属版没有导出按钮时，可在本机使用：

```sh
node tools/legacy-file.mjs --profile /path/to/client-config.json --out /path/to/restore.pvault
```

生成的恢复文件含原密钥和连接配置，必须私下保存。它不含密码记录；新软件会用该密钥解密并保留旧工作副本，服务器模式还会获取原服务器上的记录。工具不联网，也不更改旧配置或旧库。专属安装包、配置备份和恢复文件均不属于公开发布内容。

## 从源码运行与构建

Node.js 22+；Windows 构建需要 Windows 和系统自带的 .NET Framework 4.x C# 编译器。Android 构建需要 JDK 17+、Android SDK platform 35、build-tools 35.0.1。

```sh
npm ci
npm test
npm start
npm run build:windows
```

Windows 包输出到 `dist/windows/`，包括 Chrome 本机连接和通用扩展代码。扩展本身无需编译，开发安装方法见 [扩展说明](chrome/README.md)。Android 自行构建：

源码开发时可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-browser-host.ps1` 生成本机桥接程序；Chrome 注册由安装后的 Windows 包首次运行完成。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-android.ps1 -SdkRoot 'C:\Android\Sdk'
```

Android 包默认输出到 `dist/android/`，可用 `-OutputDir` 指定位置。构建脚本只打包 `ui/`、`core/` 和原生桥接；不打包 `private/`。APK 签名资料保存在项目本机的 `private/`，不提交 Git。首次自行构建会生成自己的签名密钥；发布者用同一签名密钥构建后续升级包。不能把另一个签名的 APK 覆盖安装到现有应用上，需先导出文件再迁移。

测试涵盖因果合并、删除标记、密文协议、真实 HTTP 并发、文件导入损坏与错库、模式禁网、本地存储、升级恢复、备份后新建库，以及浏览器匹配、填写、待确认保存和并发状态。Android 的构建和签名验证不能替代真实手机上的文件选择器与系统密钥测试。
