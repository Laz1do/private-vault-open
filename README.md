# 私密密码库

Windows x64 与 Android 8.0 及以上的个人密码记录软件。打开即可查看，支持离线新增、修改、删除、搜索、复制和冲突选择。通用安装包没有预置任何人的密码库、密钥或服务器地址，每次新安装在本机生成独立密码库。

源码采用 MIT 许可。安装包与源码：[GitHub Releases](https://github.com/Laz1do/private-vault-open/releases)。Windows 安装 Setup.exe，Android 安装 APK。Windows 包未购买商业代码签名；Android APK 使用项目的私有发布密钥签名。

## 两种更新方式

**文件模式（默认）**：在软件中点击“导出文件”，自行复制给另一台设备，再点击“导入文件”。每次导出是当时完整库的快照；后续编辑不会自动写回已经导出的文件。此模式不访问同步服务器。

**服务器模式**：连接你自己部署的 HTTPS 服务器。软件打开、回到前台、修改记录、恢复网络及手动同步时尝试更新；应用关闭后不做后台同步。切回文件模式保留同一份本地密码库并停止服务器同步。

导入同一库文件会合并记录，保留本机独有的新记录；旧文件不会覆盖较新修改或恢复已删除的密码。同一记录被两台设备分别修改时保留冲突版本，由你选择。没有历史版本、撤销或回收站。首次使用的新空库可以接纳已有文件；已经有记录或删除标记的库拒绝其他库的文件。相同库 ID 但密钥不同的文件也会拒绝，失败不会修改现有库。

## 文件与本机存储

**导出的 `.pvault` 文件无需密码，任何持有人都能读取密码，并获得文件内对应服务器的访问权限。** 文件含完整密码记录、库密钥、库 ID、服务器地址和访问凭据，只传递给你认可的设备。软件在导出/导入处也说明这一点。

软件自己的工作副本采用 AES-256-GCM 加密；Windows 用系统 `safeStorage` / DPAPI 保护配置，Android 用 AndroidKeyStore 保护配置。没有主密码，依靠设备账户和锁屏保护。本机配置和密文一起原子提交；损坏文件不会自动当作空库覆盖。你负责设备与导出文件的保管。

服务器只接收 AES-GCM 密文与库 ID，不接收库密钥或明文密码，使用访问凭据的 SHA-256 摘要鉴权。一个服务器实例对应一个库，其他用户自行建库和部署自己的实例。

## 自建服务器

1. 在软件中新建记录或保持空库，导出一个 `.pvault` 文件。
2. 在装有 Node.js 22 或更新版本的**本机**，用源码中的工具生成服务器配置：

   ```sh
   node tools/server-config.mjs --file /path/to/passwords.pvault --out server/server.env
   ```

   输出只有库 ID、访问凭据摘要和运行参数。工具不覆盖已有配置。密码文件、库密钥和原始访问凭据留在本机，不复制到服务器。
3. 将 `server/` 的程序和生成的 `server.env` 复制到你的服务器。按 [服务器部署说明](server/README.md) 提供 HTTPS。
4. 在软件的服务器设置中填 HTTPS 根地址，保留软件生成的访问凭据，然后切换到服务器模式。
5. 重新导出文件，交给另一台设备导入；文件会带上连接配置。另一台设备切换到服务器模式后即可下载和合并同一库。

改变访问凭据后，服务器的摘要配置也必须同步修改。修改服务器地址不改变库身份；错误的服务器库 ID 或密钥会停止同步并保留本地数据。

## 从 0.1.0 专属版升级

0.1.0 安装包自带专属密钥，0.2.0 通用安装包不再携带它。更新前保留旧安装包和专属配置备份。通用版发现旧 `vault.json` 而缺少原密钥时，会进入“导入恢复”状态，保留旧文件并暂停编辑与同步；导入带原库身份与密钥的 `.pvault` 文件后会解密原本地记录并合并，保留设备身份。

旧专属版没有导出按钮时，可在本机使用：

```sh
node tools/legacy-file.mjs --profile /path/to/client-config.json --out /path/to/restore.pvault
```

生成的恢复文件含原密钥和连接配置，必须私下保存。它不含密码记录；新软件会用该密钥解密并保留旧工作副本，服务器模式还会获取原服务器上的记录。工具不联网，也不更改旧配置或旧库。专属安装包、配置备份和恢复文件均不属于公开发布内容。

## 从源码运行与构建

Node.js 22+；Windows 构建需要 Windows。Android 构建需要 JDK 17+、Android SDK platform 35、build-tools 35.0.1。

```sh
npm ci
npm test
npm start
npm run build:windows
```

Windows 包输出到 `dist/windows/`。Android：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-android.ps1 -SdkRoot 'C:\Android\Sdk'
```

Android 包默认输出到 `dist/android/`，可用 `-OutputDir` 指定位置。构建脚本只打包 `ui/`、`core/` 和原生桥接；不打包 `private/`。APK 签名资料保存在项目本机的 `private/`，不提交 Git。首次自行构建会生成自己的签名密钥；发布者用同一签名密钥构建后续升级包。不能把另一个签名的 APK 覆盖安装到现有应用上，需先导出文件再迁移。

测试涵盖因果合并、删除标记、密文协议、真实 HTTP 并发、文件导入损坏与错库、模式禁网、本地存储和升级恢复。Android 的构建和签名验证不能替代真实手机上的文件选择器与系统密钥测试。
