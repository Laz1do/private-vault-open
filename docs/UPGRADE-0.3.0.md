# 升级到 0.3.0（Windows）

本次发布 Windows 安装包、可选 Chrome 扩展 ZIP 和源码。Android 继续使用 0.2.0 APK；恢复文件格式、服务器密文协议和同库合并规则保持兼容。

## 从 Windows 0.2.0 升级

1. 在原软件中导出当前 `.pvault` 文件，保存到自己的安全位置。
2. 从 [GitHub Releases](https://github.com/Laz1do/private-vault-open/releases) 下载 Windows 0.3.0 安装包，完成升级后打开软件。原本地密码库和同步方式继续使用。
3. “密码库”中查看记录；文件操作和同步方式迁移到“文件与恢复”。原“导出文件”现在叫“生成恢复文件”，“导入文件”现在叫“导入与合并”。

无需重新生成库密钥。新装设备在首次选择页点“从文件恢复”，导入之前保存的文件。已有同库内容会合并；有记录或删除标记的其他库不会被覆盖。相同库 ID 但密钥不同的文件也无法导入。

如果来自 0.1.0 专属安装包，仍然必须使用带原库身份和密钥的恢复文件。新密钥打不开旧库，请参照 [README 中的旧版迁移说明](../README.md#从-010-专属版升级)。发现旧库但缺少原密钥时，软件只引导导入，保留旧文件。

## 恢复文件与新建库

在“文件与恢复”点击“生成恢复文件”，可以为当前空库或已有密码库保存完整 `.pvault` 文件。它记录导出时的密码、冲突版本、删除标记、密钥和服务器连接设置；后续修改不会自动写回这份文件。

**恢复文件无需密码即可读取。请自行保管，只交给自己的设备。** 本地软件的工作副本仍使用系统保护的配置与加密密码库。

“新建密码库”是建立另一份独立的库，并切换本地工作库。流程为确认 → 选择位置并成功保存旧库的恢复文件 → 原子提交新空库。取消保存、保存失败或新库提交失败均继续使用旧库；旧服务器的数据不被删除。新库生成独立身份和密钥，从文件模式开始。切换后旧库的编辑草稿和浏览器待保存候选失效。

## 安装 Chrome 扩展

1. 在 Windows 软件的“浏览器助手”开启助手，保持软件运行。
2. 下载发布页中的 Chrome 扩展 ZIP，解压到长期保存的目录。也可以点击软件的“打开扩展目录”。
3. 在 Chrome 打开 `chrome://extensions`，开启“开发者模式”，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹。
4. 固定“私密密码库 · 浏览器助手”到工具栏，打开小窗查看连接状态。

扩展 ID 固定为 `dinagdpfpgbcfepiaabjccimnppakedl`；客户端自动注册对应的本机连接，无需手动填写 ID、导入密钥或创建浏览器账号。扩展的公开公钥只用于保持 ID，不是密码库密钥。加载目录需要长期保留，升级扩展时替换原目录内容并在扩展管理页面重新加载。

## 填写与确认保存

在 HTTPS 网站打开扩展小窗，点击匹配账号后填写账号／密码，自己点击登录。网址按 HTTPS 来源精确匹配主机名和端口：`login.example.com` 不匹配 `shop.example.com`，`example.com:8443` 不匹配默认 HTTPS 端口。没有网址或尚有冲突的记录不参与填写。

若要检测新账号或新密码，再在扩展小窗开启“网站检测”，授予所有 HTTPS 网站权限。已经打开的标签页在开启后需要重新加载，当前页会立即尝试接入。提交登录、注册或改密表单后，在扩展小窗核对来源网站和候选内容，点击“确认保存”或“确认更新”才会写入库。识别到候选不代表登录成功，可以直接忽略。

软件中的助手开关决定是否向 Chrome 提供密码库操作；扩展中的网站检测开关决定是否自动识别表单。关闭检测会撤销全部 HTTPS 网站权限，主动点选账号填写仍可使用当前标签页权限。密码、密钥和服务器凭据由本地软件管理，扩展不会把密码和账号列表写入浏览器存储。

分步登录在账号页和密码页分别点击账号。本轮只支持 HTTPS 主页面，不填写验证码、子框架或注册的新密码字段；特殊表单、跨网站分步登录和无法区分新旧密码的页面可能需要手动录入。更多限制见 [Chrome 扩展说明](../chrome/README.md)。

## 托盘、外观与同步

关闭 Windows 窗口会缩到系统托盘，仍可处理浏览器填写、确认保存和修改后的同步。双击托盘恢复窗口；托盘菜单“退出”会结束软件并断开浏览器助手。软件退出后需要重新打开，才能继续填写与保存。

界面浅深主题随系统，系统减少动态效果时收敛移动动画。`Ctrl K` 立即搜索，`Ctrl N` 新增记录。复制与搜索不等待动画。

文件模式只在本地保存，需要自行生成文件并传递更新。服务器模式继续连接自己的 HTTPS 服务器，在打开、回前台、修改记录、恢复网络和手动同步时尝试更新。Windows 托盘运行期间修改仍触发同步；Android 0.2.0 在下次打开或回前台时获取更新。现有自建服务器无需因本次界面升级迁移数据库或修改密文协议。
