# Chrome 浏览器助手（Windows）

安装私密密码库 Windows 0.3.0，并在客户端的“浏览器助手”里开启功能。关闭客户端窗口后，它会留在系统托盘继续提供填写；选择托盘“退出”后，扩展提示打开客户端。

## 安装扩展

1. 从 [GitHub 发布页](https://github.com/Laz1do/private-vault-open/releases) 下载 Chrome 扩展 ZIP，解压到自己长期保存的文件夹。
2. 在 Chrome 地址栏打开 `chrome://extensions`，开启右上角“开发者模式”。
3. 点击“加载已解压的扩展程序”，选择含 `manifest.json` 的文件夹。不要删除或移动该文件夹。
4. 将“私密密码库 · 浏览器助手”固定到工具栏，打开小窗检查连接。

扩展固定 ID：`dinagdpfpgbcfepiaabjccimnppakedl`。公开的 manifest 公钥用于保持 ID 稳定，它不是库密钥。Windows 客户端启动时为当前 Windows 用户注册这一扩展的本机连接；更换扩展 ID 后无法连接。

升级时先把 ZIP 解压到原文件夹，再在 `chrome://extensions` 点击此扩展的重新加载。Chrome 的加载方式见 [官方说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world)。

## 填写

在 HTTPS 网站打开扩展小窗，点击匹配账号。记录中的网址必须与当前页面的 HTTPS 来源完全相同：主机名和端口一致，例如 `login.example.com` 不匹配 `shop.example.com`，端口 `8443` 不匹配默认端口。`https://example.com` 与 `https://example.com:443` 会按 HTTPS 默认端口归一化，视为同一来源；网址路径不参与匹配。记录冲突要先在客户端处理。没有网址的记录不会参与填写。

账号和密码分两步的网站，需要在账号页点一次，在密码页再点一次。扩展只填写主页面的登录字段；不填写子框架、验证码、注册的新密码字段，也不自动提交登录。动态表单会在每次操作时重新识别。

## 提示保存和更新

在扩展小窗点击“网站检测 · 开启”，允许访问全部 HTTPS 网站。这项可选权限用于识别你提交的登录、注册、修改密码表单。首次开启后，已打开标签页需重新加载才能自动检测；当前页会立即尝试接入。在小窗关闭检测会撤销全部 HTTPS 网站权限，用户主动点击账号填写仍可通过当前标签页权限完成。

提交表单或点击登录／注册／改密按钮后，工具栏出现数字提示。Chrome 127 及更新版本还会尝试打开当前标签页的助手小窗；如果浏览器未允许弹出，点击工具栏图标即可查看。核对来源网站、账号、密码并“确认保存”或“确认更新”。多条账号记录由你选择，更新保留原名称和备注。识别只是候选，不表示登录成功；不需要的候选点击“忽略”。每次提交不会直接改动密码库。

待确认密码只在客户端内存中保留，最长 10 分钟；扩展不把密码、账号列表或库配置写入浏览器存储。关闭标签页、退出客户端或切换密码库后，候选可能失效，需要重新提交。验证码和无法判断新旧密码的表单不生成候选；不同主机名之间不继承上一步账号。密码记录、密钥和服务器凭据仍由本机客户端管理。

此版本的自动检测仅支持 HTTPS 主页面。特殊登录页面、跨网站分步登录、内嵌登录框或多个未标记的密码字段可能需要手动录入。2026-10-13 使用独立 Chrome 配置只读检查了 Google、GitHub 和 Microsoft 公开登录页：Google 与 Microsoft 的账号步骤、GitHub 的账号／密码字段都能识别。未使用真实账号提交登录，因此 Google／Microsoft 后续密码步骤与验证码流程没有真实账户验证；受控测试覆盖普通登录、分步页面、注册、改密和动态字段。真实网站会变化，不承诺网站的所有登录路径。

## 开发与检查

无需编译和外部依赖。项目根目录执行：

```sh
node --test chrome/tests/*.test.js
```

扩展使用 Chrome Native Messaging 与安装的 Windows 软件通信。网页只能提交待确认候选；查询、读取凭据、确认保存都由扩展自己的小窗发起。无外部网页连接入口。参考 [Chrome Native Messaging 官方文档](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)。
